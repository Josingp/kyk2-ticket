# 신인감독 김연경2 · 모바일 초대 티켓

이름 + 연락처 뒤 4자리를 입력하면 본인 초대 티켓이 화면에 표시되는 정적 웹앱입니다.
서버가 필요 없어 **GitHub Pages / Vercel에 그대로 배포**할 수 있습니다.

## 파일 구성

| 파일 | 용도 |
|---|---|
| `index.html` | 관람객용 티켓 조회 화면 |
| `verify.html` | 스태프용 검증 화면 (QR 스캔 시 자동 열림) |
| `admin.html` | (구 주소) 접속 시 메인 페이지 **관리자 탭**으로 자동 이동 |
| `api/` | Vercel 서버 함수 — DB 조회(`/api/db`) · 관리자 발행/명단(`/api/admin`) |
| `data/db.json` | 백업용 정적 DB (서버 저장소가 없거나 접속 불가할 때만 사용) |
| `assets/config.js` | 행사명 · 날짜 · 고지 문구 · 회차 솔트 설정 |
| `tools/명단_양식.xlsx` | 명단 입력 양식 |

## 운영 흐름

1. `tools/명단_양식.xlsx` 형식으로 명단 작성 — 열: `이름 / 연락처 / 구역 / 좌석 / (등급)`
   같은 사람의 좌석이 여러 개면 행을 여러 줄로 입력합니다.
2. 배포 주소 상단의 **관리자 탭**에서 비밀번호로 로그인한 뒤 엑셀을 올리면
   브라우저에서 암호화된 뒤 **서버(Upstash Redis)에 바로 적용**됩니다. 재배포 없이 즉시 반영됩니다.
3. 같은 탭의 **서버 명단 조회 · 수정**에서 현재 명단을 표로 불러와 이름/연락처/좌석을 고치거나
   행을 추가·삭제하고 다시 적용할 수 있습니다. (기존 인원의 확인코드는 유지됨)
4. `스태프_확인용_명단.xlsx`는 관리자 탭에서 언제든 다시 내려받아 입장 스태프에게만 전달합니다. (확인코드 포함)
5. 서버 적용이 실패하는 환경(GitHub Pages, Upstash 미설정)에서는 예전처럼 `db.json`을 내려받아
   저장소의 `data/db.json`을 교체하는 백업 경로가 그대로 동작합니다.

## 서버 저장소(Upstash) 설정 — 최초 1회

즉시 반영 기능은 Vercel 서버 함수 + Upstash Redis를 사용합니다. (봉고조아/배구 좌석툴과 같은 조합)

1. Vercel 프로젝트 → **Storage** → **Upstash Redis** 생성·연결 (Marketplace 연동 시
   `KV_REST_API_URL` / `KV_REST_API_TOKEN` 환경변수가 자동 주입됩니다)
   또는 Upstash 콘솔에서 REST URL/TOKEN을 복사해 환경변수
   `UPSTASH_REDIS_REST_URL` / `UPSTASH_REDIS_REST_TOKEN` 으로 직접 등록해도 됩니다.
2. 등록 후 **Redeploy** 한 번.
3. 관리자 비밀번호를 바꾸려면: 환경변수 `ADMIN_PASSWORD_SHA256`(새 비밀번호의 SHA-256 hex)을
   등록하고, `index.html`의 `ADMIN_HASH` 상수도 같은 값으로 교체하세요.
4. 관리자 API는 IP당 10분에 30회로 제한되어 무차별 대입을 막습니다.

명단 원본(이름·연락처·좌석·확인코드)은 **Upstash 안에만** 저장되고, 공개적으로 내려받을 수 있는
`/api/db` 응답과 `data/db.json`에는 지금처럼 **암호문만** 들어갑니다.

## 배포

**Vercel (권장):** vercel.com → Add New Project → 이 저장소 import → Framework: Other → Deploy
**GitHub Pages:** 저장소 Settings → Pages → Deploy from a branch → `main` / root

## 위조방지 구조

- **실시간 요소** — 초 단위 KST 시계, LIVE 펄스, 화면을 훑는 광택 애니메이션, 이름+현재시각 워터마크.
  캡처 이미지는 시계가 멈춰 있으므로 입장 시 실시간 화면만 인정하면 됩니다.
- **확인코드** — 발급 시 무작위 생성되어 암호문 안에만 존재합니다. 명단에 없는 사람은 유효한 코드를
  만들 수 없고, 스태프는 `verify.html`(티켓 QR)이나 스태프 명단으로 즉시 대조할 수 있습니다.
- **암호화 DB** — `db.json`에는 이름·연락처·좌석이 평문으로 들어 있지 않습니다.
  올바른 이름+뒤 4자리를 아는 본인만 자기 티켓을 복호화할 수 있습니다. (PBKDF2 10만 회 + AES-GCM)
- 검증은 반드시 **공식 배포 주소의 verify.html**에서 하세요. 확실히 하려면 종이 명단(스태프 확인용)과
  코드 대조가 최종 기준입니다.

## 주의사항

- 원본 명단 엑셀과 스태프 확인용 명단은 **절대 저장소에 올리지 마세요.** (`.gitignore`로 기본 차단)
- `assets/config.js`의 `salt`는 회차마다 다르게 설정하는 것을 권장하며, 바꾸면 `db.json`을 다시 생성해야 합니다.
- 8/27 장충체육관 회차는 이 저장소를 복제한 뒤 `config.js`(행사 정보·salt)만 수정하고 명단을 새로 올리면 됩니다. salt가 다르면 Upstash 안에서도 회차별로 완전히 분리 저장됩니다.
- 관람객 화면은 조회할 때마다 서버 DB를 먼저 받고, 서버가 비어 있으면 `data/db.json`을 사용합니다. 반영이 안 보이면 새로고침하세요.
